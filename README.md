## WP for July 页面代码说明

页面入口为 `#/wp-for-july`。从左侧导航点击 **WP for July** 后，`App.tsx` 会渲染 `PreWpJuly`。

### 相关文件及职责

| 文件 | 职责 |
| --- | --- |
| `App.tsx` | 注册 `wpForJuly` 视图和 `#/wp-for-july` 路由，并挂载 `PreWpJuly`。 |
| `components/Sidebar.tsx` | 左侧导航中的 WP for July 入口及选中态。 |
| `components/PreWpJuly.tsx` | 页面容器和状态协调中心；负责引言、问卷、三个阶段、两张矩阵的数据同步、保存状态、上传入口及阶段跳转。 |
| `components/InventoryMatrixJuly.tsx` | “存货了解矩阵”；负责余额、存货管理方式、存货监盘方法、其他安排等字段的展示和编辑。 |
| `components/MethodPlanMatrixJuly.tsx` | “选择存货监盘方法/监盘计划”矩阵；负责地点导入、逐行计划、异常确认、KOIC 发布预览及创建任务。 |
| `components/TableFullscreenFrameJuly.tsx` | 两张宽表共用的全屏展示外壳。 |
| `utils/inventoryAttendanceRules.ts` | “客户盘点日”和“项目组审计方案”的联动规则，例如独立盘点的自动选择与禁用逻辑。 |
| `utils/inventoryProcedureRules.ts` | 将审计方案、盘点方式、盘存系统及第三方存货组合转换为最终监盘程序；同时生成阻断项和 ISA 提示。 |
| `utils/*July*.test.mjs`、`utils/inventory*Rules.test.mjs` | WP for July 的路由、同步、导入、布局和业务规则回归测试。 |

核心页面文件是 `PreWpJuly.tsx`、`InventoryMatrixJuly.tsx` 和 `MethodPlanMatrixJuly.tsx`。修改跨表业务规则时，应优先修改 `utils` 中的规则文件，避免在两个矩阵中分别维护不同版本的判断。

### 页面流程和 UI 展现逻辑

右侧竖向步骤导航固定展示三个阶段：

1. **了解被审计单位的存货**：收集基础信息、存货性质问卷及相关说明/附件。首个问卷标题不显示大序号，内部保留 1–6 小序号；后续审计问题从序号 1 开始。
2. **存货了解矩阵**：按地点维护余额、盘存制度、盘点方案、监盘可行性和样本数量等信息。
3. **确定项目组的存货监盘方法**：根据矩阵结果形成监盘计划，确认异常后发布到 KOIC/创建任务。

页面首次进入时显示第 1 阶段。引言会自动收起；完成并保存“了解被审计单位的存货”区域后，该区域自动折叠。页面标题滚动到顶部后会固定显示，步骤导航始终位于右侧；保存按钮显示在竖向步骤 3 的下方。点击步骤圆点会平滑滚动到对应区域。

### 存货性质问卷

- 首个存货性质问卷包含 6 个子问题，覆盖多地点、存货类型/存储方式、特殊存货、外部专业机构、自动化仓库及第三方所有存货。
- 多选问题中的“不涉及”选项与其他选项互斥。
- 六个问题填写完整后才可点击“确认并生成指引”。
- 确认后，问卷卡片横向切换至审计指引卡片，并根据选择生成对应提示。
- 后续问题可填写说明；指定问题支持上传相关文件。

### 存货了解矩阵

矩阵提供默认摘要，以及 **存货余额**、**存货管理方式**、**存货监盘方法**、**其他安排**和**显示全部**五个切换选项。再次点击当前分组会返回默认摘要。

主要 UI 规则如下：

- 表头和数据字体统一为 11px；短选项（8 个汉字及以内）居中，其他下拉内容左对齐。
- 序号、公司、受访单位、存货类别、是否选为盘点对象以及当前余额固定在左侧。
- 在“存货监盘方法”视图中，`本期期末余额（百万元）`同样作为固定列展示。
- `项目组决定的存货监盘方法`固定在最右侧，并由规则自动生成，不能直接编辑。
- “显示全部”使用横向滚动；滚轮会按列宽逐列移动。
- 支持关键词搜索、是否选为盘点对象筛选、金额排序、分页和每页行数设置。
- 勾选行后可以批量编辑或固定显示删除按钮；批量编辑窗口中的地点列表为两列，可通过右上角 `×` 移除单个地点。
- 将“是否选为盘点对象”由“是”改为“否”时，必须填写样本变更原因；变更原因区域位于矩阵下方。

### 字段联动规则

1. **期末余额确认方式 → 盘存系统**
   - 通过出入库和移动记录确认：自动对应永续盘存系统。
   - 通过期末实地盘点结果确定：自动对应定期盘存系统。
2. **具体盘点计划 → 盘点方法**
   - 系统根据期末盘点、非期末盘点或循环盘点的描述自动生成盘点方法。
3. **项目组是否可以前往存货所在地点实施监盘**
   - 选择“是”：客户盘点日字段可编辑，并默认选择“是”。
   - 选择任一“否”：客户盘点日和计划的审计方案显示为空白且不可编辑；最终监盘方法根据“不可预见”或“不可行”规则自动生成。
4. **项目组前往当日客户是否开展盘点**
   - 选择“是”：审计方案中的“独立盘点方案”置灰、不可选择。
   - 选择“否，项目组采取独立盘点”：审计方案自动设为“独立盘点方案”。
5. **第三方存货**
   - 只有当前审计方案允许时，才可选择向第三方函证；方案切换为不可预见、无法实施或不可行时，该字段自动重置为“否”。
6. **最终监盘方法**
   - `inventoryProcedureRules.ts` 根据审计方案、循环/全面盘点、定期/永续盘存及第三方函证组合生成简洁程序名称，并处理 ISA 警告和阻断条件。

### 两张矩阵的数据同步

- `PreWpJuly.tsx` 持有两张矩阵的行数据，并以稳定的地点 `id` 进行映射。
- 从地点模板批量导入后，先合并到存货了解矩阵，再同步到监盘计划矩阵。
- 修改存货了解矩阵后，公司、地点、样本选择、余额和盘点相关字段会同步到监盘计划。
- 修改监盘计划中的审计方案、样本数量、第三方函证、现场/远程监盘、专家及内审利用等字段后，会回写存货了解矩阵。
- 两张表共用 `inventoryAttendanceRules.ts` 和 `inventoryProcedureRules.ts`，保证表格显示、编辑弹窗和任务发布使用同一套判断。

### 导入、发布和创建任务

- 批量导入支持直接粘贴表格数据或上传 Excel，并可下载模板/当前数据。
- 地点导入会校验必填表头；部分由系统推导的字段保持锁定。
- 发布前会按地点展示 ISA 异常或提示。阻断项不能发布，非阻断提示需要勾选确认。
- “是否选为盘点对象”为“否”的地点不会发布为任务；系统只提示存在被排除地点，不逐项列出名称。
- 可发布地点必须同时满足：被选为盘点对象、规则未阻断、已生成至少一个监盘程序、所有非阻断提示已确认。
- 发布成功后，引言和前置了解区域会折叠，并自动进入存货了解矩阵。
