# WP for July 统一矩阵设计

## 目标

将原存货了解矩阵与存货监盘计划矩阵合并为一张统一矩阵。用户在同一组地点行上，通过四个切换按钮查看和编辑不同主题的字段，不再进入第二张可见表格。现有 Excel 导入、地点同步、异常判断、程序分流和创建任务逻辑继续工作。

## 页面结构

统一矩阵沿用 `InventoryMatrixJuly` 当前的表格视觉规范，包括字体、字号、颜色、表头、单元格密度、分页、搜索、横向滚动和固定列风格。

表格左侧始终显示以下基础列：

1. `#`
2. 所属公司名称
3. 受访单位名称
4. 存货类别
5. 选为盘点对象

基础列之后显示当前切换视图对应的字段。工具栏中的原“期末余额 / 预审余额”切换器替换为四个同风格按钮：

1. 存货余额
2. 存货管理方式
3. 存货监盘方法
4. 其他安排

默认视图为“存货余额”。本次不增加“选为盘点对象”的表头筛选。

## 四个字段视图

### 存货余额

按以下顺序显示：

1. 本期期末余额（百万元）
2. 占比
3. 变动幅度
4. 上期期末余额（百万元）
5. 占比
6. 本期预审阶段余额（百万元）
7. 占比
8. 变动幅度
9. 上期预审阶段余额（百万元）
10. 占比

金额继续保留两位小数，并使用百万元单位。占比和变动幅度继续使用现有计算方式。

### 存货管理方式

按以下顺序显示：

1. 被审计单位的存货盘存系统
2. 如何确认期末存货余额
3. 被审计单位的存货盘点方案
4. 如何计划具体存货盘点
5. 存放在第三方地点？
6. 被审计单位是否使用专家

继续沿用现有下拉选项、说明按钮和字段间联动。

### 存货监盘方法

按以下顺序显示：

1. 存货所在地点是否可以前往①
2. 客户当日是否开展盘点②
3. 项目组就监盘而计划的审计方案③
4. 样本数量
5. 确认的存货监盘方法
6. 操作

①和②均为可编辑的“是 / 否”字段。当前阶段不根据①或②自动筛选、限制或改写③的审计方案。

“操作”继续打开现有地点设置能力。“创建任务”按钮放在该视图工具栏右侧，打开现有创建任务窗口。

### 其他安排

按以下顺序显示：

1. 是否向存放在第三方地点的存货发出函证
2. 现场监盘 vs 远程监盘
3. 计划引入专家和/或特定项目组成员
4. 利用内审获取审计证据

继续沿用现有可选项、禁用状态和说明信息。

## 数据模型与同步

统一矩阵的地点行成为页面上的唯一编辑入口。`InventoryMatrixRow` 扩展为同时承载原了解矩阵字段和原计划矩阵字段，包括①、②、审计方案、样本数量、第三方函证、监盘方式、项目组专家和内部审计。

`PreWpJuly` 继续维护任务创建所需的 `MethodPlanRow` 数据，但它变为统一矩阵背后的兼容数据结构。每次统一矩阵行更新时，按地点行标识同步对应的 `MethodPlanRow`，避免使用数组位置匹配。Excel 导入产生的计划字段也回填到统一矩阵行。

`MethodPlanMatrixJuly` 不再渲染第二张可见表格。其创建任务窗口、异常列表、Appendix 分流、永久阻断、第三方证据判定和发布函数继续复用。打开创建任务窗口的控制入口由统一矩阵“存货监盘方法”视图触发。

## 行操作与状态

- 新增地点时，同时创建完整的统一行数据和对应计划数据默认值。
- 删除地点时，同时移除对应计划数据，避免留下不可见任务。
- “选为盘点对象”为“否”的地点继续不进入任务创建范围。
- 搜索、分页和切换视图不改变行数据或当前选择。
- 切换视图后回到原视图，已编辑字段保持不变。
- 创建任务窗口中的警告异常复选框、全选、永久阻断和确定发布行为保持现状。

## 验证

实施后验证以下行为：

1. 四个按钮显示正确字段，并保持现有表格视觉风格。
2. 五个基础列在四个视图中始终显示。
3. 余额字段顺序、单位、两位小数、占比和变动幅度正确。
4. ①和②可独立选择“是 / 否”，且不改变③。
5. 原第二张表不再显示。
6. “存货监盘方法”视图可以打开创建任务窗口。
7. Excel 导入、新增、删除、搜索和分页后，统一行与任务数据仍按地点正确对应。
8. 异常、永久阻断、第三方证据和任务发布回归测试通过。
9. TypeScript 检查和生产构建通过。
